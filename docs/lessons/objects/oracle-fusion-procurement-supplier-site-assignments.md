# Supplier Site Assignments

- Product/release: Oracle Fusion Cloud Procurement 26C; API `11.13.18.05`.
- Collection: `/suppliers/{SupplierId}/child/sites/{SupplierSiteId}/child/assignments`; item key: `AssignmentId`.
- Documented operations: GET, POST, PATCH. Source: [26C endpoint index](https://docs.oracle.com/en/cloud/saas/procurement/26c/fapra/rest-endpoints.html).
- Current BO functions: `ListSupplierSiteAssignments` and `CreateSupplierSiteAssignment`.

## POST

Resolve supplier, site and an authorized procurement business unit in scope. The target tenant requires both `ClientBUId` and `BillToBUId`; the golden path uses the same explicitly selected BU for both. Omit generated `AssignmentId`, ship-to, account, distribution, tax, inactive-date, DFF, attachment and payment fields. The initial Client-BU-only POST was rejected before a record existed; read-only reconciliation returned zero. The corrected POST returned `AssignmentId=300000333814296`, and an independent GET matched the assignment plus both BU IDs. Include `BillToBUId` in the GET projection before judging persistence; do not repeat a POST merely because a verification projection omitted a field.

First successful BO GET sample (2026-09-23): `{"items":[{"AssignmentId":"300000333814296","ClientBUId":"300000046987012","ClientBU":"US1 Business Unit","BillToBUId":"300000046987012","BillToBU":"US1 Business Unit"}],"count":1,"hasMore":false}`.

Change history: 2026-09-23 — recorded target-tenant required fields, autogenerated ID, corrected GET projection and independent persisted GET.
